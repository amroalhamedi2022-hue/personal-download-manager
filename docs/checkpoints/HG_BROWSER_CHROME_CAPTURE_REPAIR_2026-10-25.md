## Functional change and regression

Reused the installed `DownloadManagerCli.exe download show --status-lines` RPC path to start/wait for the installed GUI **without adding a task** before the real Chrome browser-origin `add`. A deliberately nonexistent numeric ID produces no download output but requires successful IPC and `awaitAppBoot`; a nonzero exit, timeout or unexpected output fails the test without printing sensitive stdout/stderr. The real Chrome extension, browser-origin native host, loopback fixture GET, on-disk 2 MiB SHA-256 and 120-second deadline remain strict. If `add` fails, expose only `INVALID_REQUEST`, `REQUEST_FAILED`, or `UNCLASSIFIED` classification, never native payload, URL, headers, cookies, exception text or filesystem paths. Five source regression assertions added and wired into source-only CI. No new dependency; existing Kotlin/Clikt CLI, browser MV3 extension and Apache-2.0 code are reused. No production protocol, native host identity, installer data or GUI settings are changed.

**Pre-build test question:** With the installed GUI/IPC confirmed ready, can a real Chrome MV3 extension send `add` through the installed native host and produce an actual SHA-matching 2 MiB file? **Expected:** one exact-SHA Windows NSIS installer, installed native host and Chrome pings/port/reconnect PASS, GUI/IPC warmup PASS, browser `add` correlated true, fixture actual GET > 0, final 2 MiB SHA match, sanitized evidence artifact. If it still fails, capture only the safe native error class to distinguish malformed request from IPC/backend failure. Source-only tests cannot prove Chrome origin allowlist, Windows RPC readiness, GUI side effects, network bytes or installed file persistence. The existing Windows native-host workflow will run once from this coherent code+test commit; no duplicate manual dispatch.

**Important limitation:** This gate tests browser capture **with the GUI running**. Native-host-triggered GUI cold start without CLI warmup remains **NOT TESTED** and must be verified separately; do not mislabel warm capture as cold-start success.
