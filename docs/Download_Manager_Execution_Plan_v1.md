# خطة تنفيذ مدير التحميل الشخصي — المرجع التنفيذي

الإصدار: 2.0 | التاريخ: 2026-10-17 | المنطقة الزمنية: Asia/Hebron

المُنفّذ المستهدف: GPT-5.6 Sol High، أو أي نموذج يتابع المشروع لاحقًا.

**الحالة: اكتملت P0 واعتمد المستخدم مرجع نافذة تحميل الملف النهائي. في P1 اكتمل Baseline وفصل الهوية والرفع الخاص، ونجحت اختبارات المحرك وCompile وحزمة Windows على GitHub Actions؛ يبقى P1-07 جزئيًا كتدقيق provenance/PGP أعمق للاعتماديات. جزء P3-03 الخاص بشريطي السائل أصبح مجمّعًا على Windows لكنه ما زال يحتاج تجربة بصرية وتشغيلية فعلية.**

إنشاء هذا الملف ليس إذنًا ببدء البرمجة. يجب انتظار موافقة صريحة من المستخدم. بعد الموافقة، اتبع المراحل بالترتيب وحدّث هذا الملف بالأدلة، ولا تحوّل الخطة كلها إلى دفعة تنفيذ واحدة.

## 1. طريقة استخدام هذا الملف

1. اقرأ الملف كاملًا قبل أي عمل. اقرأ آخر سجل تقدم وأي تعليمات أحدث من المستخدم.
2. تحقق من حالة المستودع والتغييرات الموجودة دون حذفها أو استبدالها.
3. اختر أصغر مجموعة مهام مترابطة من أول مرحلة غير مكتملة. يمكن إنجاز أكثر من مهمة في دفعة واحدة إذا كانت مستقلة أو قابلة للتحقق معًا.
4. اشرح للمستخدم: أين وصلنا، ماذا ستنفّذ، وكيف ستتحقق.
5. نفّذ فقط ضمن الإذن الممنوح. التزم بالتوثيق الرسمي والمراجع المناسبة وفحص التراخيص.
6. شغّل الاختبارات المتاحة، وسجّل ما نجح وما فشل وما لم يمكن تشغيله.
7. حدّث قائمة التحقق وسجل الأدلة والمشاكل في الملف نفسه؛ لا تُنشئ مرجعًا منافسًا مبعثرًا.
8. لا تعلن اكتمال مرحلة قبل تحقيق شرط خروجها. العائق في ميزة لا يمنع العمل المستقل الآمن، لكنه يمنع إعلان نجاحها.
9. في نهاية كل دفعة: ملخص التغيير، نتيجة الاختبارات، المخاطر، والخطوة التالية.

### حالات العمل

- مخطط: لم يُنفّذ.
- قيد التنفيذ: العمل جارٍ ولم يُعتمد.
- منفذ غير متحقق: يوجد كود، لكن الأدلة غير كافية.
- مختبر آليًا: نجحت اختبارات محددة مع ذكر بيئتها.
- مجرّب على Windows: نجح سيناريو فعلي على نسخة Windows مع ذكر الإصدار والبيئة.
- مكتمل: تحققت شروط القبول وسُجل الدليل.
- محجوب: يحتاج قرارًا أو إذنًا أو بيئة أو موقعًا للاختبار.
- مؤجل: محفوظ في النطاق مع سبب واضح، وليس محذوفًا.

لا تضع [x] أمام مهمة لمجرد كتابة الكود أو نجاح التجميع. ضع علامة الاكتمال بعد دليل مناسب لطبيعتها. لا تُسمِّ مراجعة المصدر اختبار تشغيل.

## 2. عقد النطاق والقرارات الثابتة

- المنتج شخصي للمستخدم، وليس مشروع نشر عام حاليًا.
- Windows أولًا؛ Android لاحقًا بعد استقرار Windows وبموافقة منفصلة.
- الهدف: تجربة IDM المألوفة مع جامع روابط وحِزم شبيه بـJDownloader.
- AB Download Manager هو الأساس المختار مبدئيًا. لا بناء من الصفر ولا تغيير للقاعدة بصمت.
- المحرك والبيانات والمنطق القابل للمشاركة منفصلة عن تكاملات Windows؛ واجهة Android لاحقًا مناسبة للجوال، وليست تصغيرًا لنافذة الكمبيوتر.
- لا حساب سحابي إجباري، لا إعلانات، لا تتبع استخدام افتراضي، ولا رفع كلمات مرور أو Cookies أو سجل تحميلات لخادم تابع لنا.
- واجهة Windows قريبة جدًا من IDM في توزيع العناصر والتفاعلات والاختصارات، مع اسم وأصول رسومية خاصة بنا.
- إعدادات شاملة لكن منظمة: وضع أساسي، وضع متقدم، بحث، شرح للقيم، وإعادة ضبط لكل قسم.
- المستخدم غير مطالب ببرمجة Plugins أو اختيار كل المواقع الآن. إطار الإضافات أولًا، ودعم المواقع لاحقًا من الإعدادات.
- لا تشغيل تلقائي لملفات EXE أو مثبتات الألعاب. فك الضغط اختياري. لا حذف تلقائي للأجزاء افتراضيًا.
- لا وعد بدعم كل المواقع أو بسرعة تتفوق على IDM قبل قياسات حقيقية.
- لا دمج وحدات تجاوز DRM أو كسر حماية وصول المواقع ضمن هذا النطاق. تعامل Captcha المعتمد: مسار مدعوم لكل موقع، مع تدخل المستخدم عند الحاجة، دون وعد بحل آلي شامل.
- لا حذف ميزة طلبها المستخدم بسبب صعوبتها؛ صنّفها مؤجلة أو محجوبة واطلب القرار عند الحاجة.
- دعم YouTube مطلب صريح عبر وحدة وسائط قابلة للتحديث، مع اختيار الجودة والصوت والترجمة والقوائم حيث يدعم المصدر، ودون وعد بالمحتوى المحمي أو غير المصرح به.
- Refresh URL مطلب صريح بثلاثة مسارات: تلقائي عبر المصدر/Plugin، بمساعدة المتصفح، ويدوي؛ لا استكمال قبل التحقق من هوية الملف.
- نظام التحديث مطلب صريح، ويفصل بين تحديث التطبيق، إضافة Edge، Plugins، ومحرك yt-dlp؛ الفحص من الإنترنت، والتحقق من المصدر والسلامة، وموافقة المستخدم افتراضيًا قبل التثبيت.
- الواجهة تحافظ على ترتيب IDM المألوف وقوائمه الرئيسية، مع تصميم حديث خاص بنا، و8 عائلات ألوان: نيلي، رملي، برغندي، قرمزي، زمردي، نعناعي، جليدي، ولؤلؤي. لكل عائلة وضع Light ووضع Dark، أي 16 نسخة مظهر قابلة للاختيار، إضافة إلى خيار اتباع وضع Windows.
- حزم الأيقونات المطلوبة اثنتان: Modern Outline ملونة مستوحاة من مراجع المستخدم، وSimple بسيطة شبيهة بالنموذج الأول. حجم الأيقونات قابل للاختيار Small/Medium/Large ويحفظ لكل مستخدم دون كسر High DPI أو RTL.
- Tray جزء أساسي: تصغير اختياري إلى Tray، إظهار/إخفاء النافذة، بدء/إيقاف/إيقاف مؤقت للطوابير، محدد السرعة، فتح الإعدادات والتحديثات، والخروج الواضح. الإغلاق لا يعني الخروج إلا وفق إعداد صريح.
- نافذة/زر «Download this video» العائم وDrop Target ميزتان اختياريّتان يمكن إظهارهما وإخفاؤهما من الواجهة، وتظهران فقط عندما يوجد محتوى مدعوم.
- جدول التحميلات يعرض معدل النقل/السرعة بوضوح، ويملك نافذة أعمدة شبيهة بمرجع IDM تسمح بإظهار وإخفاء وترتيب الأعمدة وتغيير عرض العمود واستعادة الافتراضيات.
- مرجع نافذة تحميل الملف المعتمد هو `docs/design/file-download-window-approved-2026-10-17.webp` مع مواصفات `docs/design/APPROVED_FILE_DOWNLOAD_WINDOW.md`. تظهر النسبة في عنوان النافذة فقط، ولا تُكرر عند يمين شريط التقدم الرئيسي.
- دعم Torrent مطلب مستقبلي منفصل عن محرك HTTP/الوسائط: صفحة وتصنيف وقائمة وإحصاءات وإعدادات مستقلة، مع دعم ملفات `.torrent` وروابط Magnet إذا أثبتت المكتبة المختارة ذلك. لا يختلط معدل النقل أو الحالات أو سياسات الـSeeding مع التنزيلات العادية، ولا يحجب هذا المطلب مراحل Windows الأساسية الحالية.

## 4. تصحيحات ملزمة للوعود السابقة

1. Plugin ليس دعمًا سحريًا: إضافات JDownloader لا تعمل تلقائيًا داخل برنامجنا، وتغيير المواقع قد يكسر إضافاتها.
2. وجود part01 إلى part19 لا يثبت أن الحزمة تتكون من 19 جزءًا. العدد المتوقع يجب أن يستند إلى قائمة مصدر أو بيانات أرشيف أو دليل آخر؛ وإلا يظهر «غير معروف».
3. تشابه اسم الملف أو حجمه لا يكفي لخلط أجزاء من مرايا مختلفة أو إصدارين للعبة.
4. حل Captcha في المتصفح لا يضمن نقل الجلسة أو رابط التحميل للتطبيق. تعامل معها حسب الموقع، ووفّر الرجوع للمتصفح عند عدم الدعم.
5. نجاح نقل Cookies لا يلغي قيود الموقع أو صلاحية الرابط أو حدود الحساب.
6. تشفير نقل HTTPS ليس DRM. ولا يُصنّف كل HLS مشفّر تلقائيًا كـDRM؛ صنّف الحالة بدقة دون وعد بالتعامل مع محتوى محمي.
7. إعداد الملف يخصص القيم الموروثة لكنه لا يتجاوز سقف السرعة أو الاتصالات العام أو قيود الخادم.
8. تصريح صلاحيات Plugin في ملف لا يصنع عزلاً أمنيًا. لا تُسمَّ الإضافة معزولة دون آلية إنفاذ واختبارات سلبية.
9. «نفس البرنامج» لا يعني مزامنة سحابية تلقائية بين الأجهزة؛ تلك ميزة مستقبلية تحتاج قرارًا منفصلًا.

## 5. هيكل التنفيذ المقترح

احتفظ بوحدات المصدر المناسبة، ولا تعِد تقسيم كل المشروع لمجرد مطابقته للأسماء التالية. المطلوب حدود واضحة للمسؤوليات:

- Download Core: HTTP، الأجزاء، الاستكمال، التحقق من هوية الملف وسلامة البيانات.
- Task/Queue Service: المهام، الحالات، الجدولة، إعادة المحاولة، حفظ التقدم.
- Link Collector: استخراج الروابط، إزالة التكرار، عمق الفحص وحدوده.
- Package Service: أجزاء الحزمة، عددها المتوقع، المرايا، كلمة مرور الأرشيف.
- Plugin Interface: إضافات جمع الروابط وإضافات الاستضافة، التوافق والإعدادات.
- Browser Bridge: قناة موثقة بين إضافة المتصفح والتطبيق، مع التحقق من كل طلب.
- Media/Archive Services: معالجة الوسائط وفك الضغط والتحقق، دون تشغيل ملفات.
- Torrent Service: محرك اختياري معزول منطقيًا وبيانيًا عن HTTP والوسائط، بحدود سرعة واتصالات وSeeding وخصوصية مستقلة.
- Windows UI/Integration: الواجهة، Tray، الإشعارات، Clipboard، إجراءات الجهاز.
- Settings/Security: القيم الافتراضية، الأولويات، حماية الأسرار، التحديث والنسخ الاحتياطي.

### نماذج البيانات التي يجب حسمها مبكرًا

DownloadItem، Package، Part، Source/Mirror، Queue، SiteProfile، CredentialReference، PluginDescriptor، CaptchaTask، VerificationResult. وللوحدة المستقبلية: TorrentTask وTorrentFile وInfoHash وTracker/PeerState دون خلطها قسرًا مع Part الخاص بـHTTP.

يجب حفظ رابط الصفحة الأصلي منفصلًا عن رابط التحميل المؤقت، وربط المهمة بحزمتها وإضافتها وحسابها دون نسخ الأسرار إلى كل سجل. لا تفترض استخدام قاعدة بيانات جديدة؛ قيّم تخزين AB أولًا ثم وثّق القرار.

### P2 — موثوقية المحرك والحفظ

- [ ] P2-01 التحقق من التنزيل باتصال واحد ومتعدد وديناميكي باستخدام ملفات معروفة البصمة. الحالة الجزئية: اتصال Range حقيقي واحد تحقق من البايتات والبصمات في E013؛ ما زال التنزيل الكامل متعدد وديناميكي مطلوبًا.
- [ ] P2-02 اختبار Range وContent-Range وETag/Last-Modified واستجابات 200/206/416، ومنع استكمال ملف تغيّر. الحالة الجزئية: 200/206/416 والـHeaders والبايتات اختُبرت بخادم محلي حقيقي في E013؛ ما زال اختبار منع الاستكمال عند تغير الطول أو ETag مطلوبًا.
- [ ] P2-03 حفظ التقدم بصورة متسقة مع البيانات المكتوبة؛ اختبار التعطل القسري والاستعادة.
- [ ] P2-04 التوقف والاستكمال والإلغاء وحذف القائمة مقابل حذف الملف؛ تأكيد واضح قبل الحذف المادي.
- [ ] P2-05 إعادة محاولة محدودة بتأخير متزايد؛ احترام 429 وRetry-After وحدود كل موقع.
- [ ] P2-06 معالجة انقطاع الإنترنت وTimeout وأخطاء 5xx وتغير الشبكة دون إتلاف الملف.
- [ ] P2-07 حد سرعة واتصالات كلي، وحدود للموقع والطابور والملف مع أولويات مفهومة.
- [ ] P2-08 معالجة امتلاء القرص والأسماء المتعارضة والأسماء العربية والمسارات الطويلة والملفات الأكبر من 4GB.
- [ ] P2-09 عرض «الحجم/الوقت غير معروف» بدل تقديرات مضللة عندما تغيب البيانات.
- [ ] P2-10 تثبيت الجداول والطوابير والتصنيفات وإعادة المحاولة، مع عدم تكرار المهام بعد إعادة التشغيل.

شرط الخروج: اجتياز T01–T08 وT18 ذات الصلة أدناه. لا تحسين سرعة على حساب سلامة البيانات.

### P3 — واجهة Windows والإعدادات

- [ ] P3-01 تنفيذ الشكل المعتمد: قوائم Tasks/Downloads/View المألوفة، Toolbar، شجرة تصنيفات/طوابير، جدول مركزي، وشريط حالة، دون نسخ أصول IDM الرسومية.
- [ ] P3-02 إضافة رابط/استكمال/إيقاف/إيقاف الكل/حذف/حذف المكتمل/خيارات/جدولة/بدء وإيقاف طابور.
- [ ] P3-03 نوافذ إضافة وتقدم وخصائص وإكمال التحميل؛ عرض الاتصالات والأجزاء إن كان مفيدًا دون تعقيد. الحالة الجزئية: نافذة التقدم الموجودة حُدثت وفق مرجع المستخدم، مع شريط إجمالي وشريط أجزاء بتأثير سائل وفقاعات وألوان `primary/secondary` للثيم؛ لم تُعتمد كمكتملة قبل Build وتجربة Windows.
- [ ] P3-04 أعمدة قابلة للترتيب والتحجيم والإخفاء، تتضمن معدل النقل/السرعة، مع نافذة اختيار أعمدة وترتيب فوق/تحت وإظهار/إخفاء وعرض بالبيكسل واستعادة الافتراضيات؛ إضافة فرز وبحث وتحديد متعدد وكليك يمين واختصارات.
- [ ] P3-05 دعم High DPI، العربية وRTL، والتنقل بلوحة المفاتيح؛ تنفيذ 8 عائلات ألوان (نيلي، رملي، برغندي، قرمزي، زمردي، نعناعي، جليدي، لؤلؤي) × Light/Dark = 16 مظهرًا، وخيار اتباع النظام؛ حزمتا أيقونات Modern Outline وSimple، وأحجام Small/Medium/Large، مع حفظ الاختيارات.
- [ ] P3-06 إعدادات أساسية ومتقدمة، بحث، وصف لكل خيار، قيم افتراضية آمنة، وإعادة ضبط القسم.
- [ ] P3-07 تصدير/استيراد إعدادات غير سرية ونسخ احتياطي؛ حماية منفصلة إذا طلب المستخدم تصدير الأسرار.
- [ ] P3-08 Tray كامل: تصغير/إغلاق إلى Tray حسب الإعداد، إظهار/إخفاء، تحكم سريع بالطوابير والسرعة، إعدادات وتحديث وخروج؛ مع إشعارات وأصوات وبدء تشغيل اختيارية وإعداد لتقليل الإزعاج.

شرط الخروج: مراجعة المستخدم لتجربة مألوفة فعلًا، واختبار T15. الشكل ليس سببًا لإخفاء أخطاء أو حالات معلقة.

### P4 — المتصفح والروابط المنتهية

- [ ] P4-01 تكييف الإضافة الرسمية للمتصفح الأساسي؛ إضافة المتصفحات الأخرى تدريجيًا مع اختبارها منفصلة.
- [ ] P4-02 قناة محلية مؤمنة مع هوية الإضافة والتحقق من مدخلات الصفحة. فضّل Native Messaging عند ملاءمته.
- [ ] P4-03 Add URL، الروابط المحددة، Download All بمرشحات، إرسال الصفحة، والتقاط التحميل التلقائي الاختياري، وزر «Download this video» عائم قابل للتعطيل للمحتوى المدعوم.
- [ ] P4-04 استثناءات المواقع والامتدادات، مفاتيح السماح/التجاوز، وClipboard مراقب اختياريًا.
- [ ] P4-05 نقل Headers/Cookies اللازمة للطلب فقط وبصلاحيات واضحة؛ لا جمع سجل التصفح ولا تصدير جلسات الحسابات عشوائيًا.
- [ ] P4-06 إذا رفض التطبيق المهمة أو كان مغلقًا، وفّر رجوعًا واضحًا لتنزيل المتصفح دون فقدان الطلب.
- [ ] P4-07 مسار Refresh Download Address: إعادة فتح المصدر، التقاط بديل، التحقق من هوية الملف قبل الاستكمال.
- [ ] P4-08 حفظ الحسابات بحماية نظام Windows، وإخفاء الأسرار من السجلات والواجهة والتقارير.

شرط الخروج: اجتياز T09 وT12، وتجربة فعلية على المتصفح المعتمد. تشغيل المتصفح وحده ليس إثبات تكامل.

### P5 — جامع الروابط والحِزم وإطار Plugins

- [ ] P5-01 إدخال رابط صفحة أو قائمة نصية أو روابط Clipboard، مع حدود لعمق الفحص وعدد الروابط والوقت.
- [ ] P5-02 تنظيف الروابط وإزالة التكرار دون إسقاط Query parameters الضرورية أو دمج موارد مختلفة خطأً.
- [ ] P5-03 شاشة مراجعة: الاسم، العدد، الحجم المعروف، المصدر، الحالة، المسار، وبدء/إضافة للطابور.
- [ ] P5-04 تجميع الأجزاء وترتيبها رقميًا وتخزين العدد المتوقع ومصدر معرفته؛ حالة «غير معروف» صريحة.
- [ ] P5-05 حالات متاحة/معطلة/غير مؤكدة/تحتاج حسابًا/تنتظر Captcha؛ لا تساوِ فشل HEAD بعدم وجود الملف.
- [ ] P5-06 خيارات Auto Confirm/Auto Start للمصادر المختارة فقط؛ الافتراضي مراجعة قبل التنزيل.
- [ ] P5-07 API للإضافات: Crawler/Host، إصدارات وتوافق وإلغاء وTimeout وأخطاء منظمة واختبارات.
- [ ] P5-08 إعدادات الإضافات: استيراد، تفعيل، تعطيل، إصدار، اختبار، وتحديث موثوق مع رجوع لإصدار سابق.
- [ ] P5-09 ابدأ بقواعد محدودة وإضافات موثوقة؛ الكود التنفيذي العام يحتاج عزلاً فعليًا وتصميمًا أمنيًا قبل السماح به.
- [ ] P5-10 استخدم موقع اختبار محليًا لإثبات الواجهة دون انتظار اختيار المستخدم للمواقع الحقيقية.

شرط الخروج: إضافة تجريبية تجمع حزمة متعددة الأجزاء وتتعامل مع أخطاء متعمدة. لا ادعاء دعم مواقع لم تُختبر.

### P6 — مواقع فعلية وCaptcha ومرايا وأرشيفات

- [ ] P6-01 عند تفرغ المستخدم، اختيار عينة صغيرة من المواقع مع روابط اختبار مصرح بها؛ لا تطلب منه كتابة Plugins.
- [ ] P6-02 توثيق دعم كل موقع: جمع روابط، تنزيل، حساب، Captcha، تجديد رابط، وحدود معروفة.
- [ ] P6-03 قائمة انتظار Captcha واحدة فعالة افتراضيًا؛ حل المستخدم، تأجيل، انتهاء صلاحية، إلغاء، إشعار، واستمرار المهام الأخرى.
- [ ] P6-04 الرجوع للمتصفح عند عدم الدعم؛ عدم تخزين حلول قديمة أو افتراض قابليتها لإعادة الاستخدام.
- [ ] P6-05 تفضيل مضيف وتخطي مرآة معطلة، وعدم خلط بيانات إلا بعد تحقق موثوق من تطابق الملف.
- [ ] P6-06 كشف الأجزاء الناقصة حيث تتوفر أدلة، وإظهار غير المؤكد بوضوح.
- [ ] P6-07 اختيار مكتبة/أداة أرشفة موثوقة بعد مراجعة الترخيص؛ RAR متعدد الأجزاء وZIP و7z حسب الدعم الفعلي.
- [ ] P6-08 فك الضغط اختياريًا، كلمة مرور يوفرها المستخدم، اختبار سلامة، مساحة كافية، وعدم تشغيل أو حذف تلقائي.
- [ ] P6-09 منع Path Traversal وSymlink escape ووضع حدود تمنع استنزاف القرص بالأرشيفات الضخمة.

شرط الخروج: T10–T14 ناجحة للمواقع/الصيغ المعلنة. أي موقع غير متاح يظل «غير مختبر» ولا يحجب الميزات المستقلة.

### P7 — الوسائط والمطابقة المتقدمة لـIDM

- [ ] P7-01 التقاط وسائط مدعومة، قوائم HLS الرئيسية/الفرعية وDASH، وYouTube بواسطة وحدة yt-dlp قابلة للتحديث، مع اختيار الجودة والصوت والترجمة والقوائم عندما تتوفر.
- [ ] P7-02 دمج الصوت والفيديو بأداة موثوقة، إظهار التقدم والفشل، وعدم حذف المصادر قبل نجاح التحقق.
- [ ] P7-03 تحديد نطاق البث الحي منفصلًا؛ لا افتراض أن تنزيل الفيديو المسجل يثبت دعم Live.
- [ ] P7-04 Site Grabber بمرشحات نطاق وعمق وأنواع ملفات وحجم وحدود طلبات؛ معاينة قبل تنزيل واسع.
- [ ] P7-05 معاينة ZIP عبر طلبات جزئية حين يدعم الخادم والصيغة، مع شرح بديل عند عدم الدعم.
- [ ] P7-06 حصص تنزيل يومية/زمنية، مزامنة دورية، وجدولة دقيقة؛ تجنب استبدال ملفات المستخدم بصمت.
- [ ] P7-07 فحص فيروسات اختياري، Shutdown/Sleep والخروج بعد اكتمال كل أعمال الحزمة مع عد تنازلي قابل للإلغاء.
- [ ] P7-08 Proxy/SOCKS/PAC، المصادقة وإعدادات المواقع وUser-Agent: جرد دعم الموجود واختباره بدل الادعاء الشامل.
- [ ] P7-09 مراجعة FTP/MMS، أنماط المصادقة القديمة، الاتصال الهاتفي، وتشغيل أمر بعد الإكمال كعناصر قرار؛ لا حذفها ولا تأخير النسخة الأساسية بها دون داعٍ.
- [ ] P7-10 مراجعة CLI/API والاستيراد والتصدير والسحب والإفلات والنافذة العائمة مقابل النطاق؛ API غير الضروري معطل افتراضيًا.
- [ ] P7-11 تقييم وتنفيذ Torrent كوحدة مستقلة: اختيار مكتبة مرخصة وموثوقة، ملفات `.torrent` وMagnet، اختيار الملفات، Pause/Resume، فحص Hash، حدود Download/Upload وSeeding، Trackers/DHT/Peers حسب الدعم، وصفحة وتصنيف وإعدادات وإحصاءات لا تختلط بتنزيلات HTTP. يبدأ بعد استقرار المحرك الأساسي ولا يحجب P2–P4.

شرط الخروج: مصفوفة مطابقة نهائية لكل بند: مختبر/جزئي/مؤجل بموافقة/غير مدعوم مع سبب. لا عبارة «كل ميزات IDM» بلا هذه المصفوفة.

### P8 — اعتماد Windows الشخصي

- [ ] P8-01 بناء حزمة تثبيت قابلة لإعادة الإنتاج؛ خيار Portable يُقيّم حسب الحاجة ولا يفترض نقل الأسرار بين الأجهزة.

- [ ] P8-03 نسخة احتياطية قبل ترقية مخطط البيانات واختبار الرجوع أو توضيح حدوده.
- [ ] P8-04 اختبار شامل على Windows الفعلي والمتصفحات المعتمدة؛ توثيق ما تم على جهاز المستخدم وما تم في بيئة أخرى.
- [ ] P8-05 قياس سرعة/CPU/RAM/قرص في ظروف قابلة للمقارنة؛ ليس عدد الاتصالات الأعلى ضمان سرعة أعلى.
- [ ] P8-06 اختبار 1,000 و10,000 رابط ودفعات حِزم دون تجمد الواجهة؛ تحديد ميزانية أداء بناءً على القياس.
- [ ] P8-07 مراجعة الأمان والتراخيص والأسرار وتحديثات الإضافات؛ لا شهادة أمان مطلقة.
- [ ] P8-08 تسليم تقرير قبول بالاختبارات الناجحة والفاشلة والمؤجلة والمشاكل المعروفة وطريقة الاستعادة.

شرط الخروج: جميع الاختبارات الحرجة ناجحة، ولا مشكلة مفتوحة تهدد البيانات أو الأسرار. توقيع التطبيق وتوزيعه العام قرار منفصل؛ لا وعد بإزالة تحذيرات Windows دون تحقق.

شرط الخروج: خطة Android معتمدة مستقلة واختبارات خاصة بالمنصة؛ لا إعلان تطابق تقني كامل بين النظامين.

| Torrent (مستقل) | مجلد وحالة وقائمة خاصة، اختيار الملفات، حدود Download/Upload، اتصالات، Seeding ratio/time، Trackers/DHT، وتوقف/استئناف؛ لا يرث إعدادات HTTP بصمت |
| أمان وصيانة | حماية أسرار، تنقيح Logs، نسخ احتياطي، استيراد وتصدير، تحديث ورجوع |

لا يعني «إعدادات لكل شيء» كشف مفاتيح داخلية خطرة أو تعطيل TLS افتراضيًا. أي خيار خطير يحتاج تفسيرًا وحماية، ولا يتجاوز ثوابت سلامة البيانات.

## 10. بوابة الجودة لكل تغيير

- [ ] رُبط التغيير بمعرّف مهمة ومتطلب واضح.
- [ ] روجعت الوثائق الرسمية والمشاريع المشابهة عند ملاءمتها، وسُجل ما استُفيد منه؛ لا بحث شكلي لكل سطر.
- [ ] تحققت التراخيص والتوافق قبل نسخ أو دمج كود، دون افتراض أن كل كود منشور مباح النسخ.
- [ ] أصغر تغيير يحقق الهدف ويحافظ على تعديلات المستخدم.
- [ ] اختبارات نجاح وفشل وحدود، واختبار يمنع رجوع العطل عند إصلاح Bug.
- [ ] نجاح Build/Lint/Tests المناسبة أو توثيق تعذرها دون ادعاء نجاح.
- [ ] تجربة Windows للميزات الخاصة بـWindows؛ اختبارات Linux لا تكفي لها.
- [ ] لا أسرار في Logs أو لقطات أو تقارير أو ملفات محفوظة.
- [ ] لا خسارة بيانات أو أثر تدميري غير مصرح؛ نسخة احتياطية قبل ترقية التخزين.
- [ ] تحديث حالة المهمة والأدلة والمشاكل والخطوة التالية.
