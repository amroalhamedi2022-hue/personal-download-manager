## 1. طريقة استخدام هذا الملف

1. اقرأ الملف كاملًا قبل أي عمل. اقرأ آخر سجل تقدم وأي تعليمات أحدث من المستخدم.
2. تحقق من حالة المستودع والتغييرات الموجودة دون حذفها أو استبدالها.
3. اختر أصغر مجموعة مهام مترابطة من أول مرحلة غير مكتملة. يمكن إنجاز أكثر من مهمة في دفعة واحدة إذا كانت مستقلة أو قابلة للتحقق معًا.
4. اشرح للمستخدم: أين وصلنا، ماذا ستنفّذ، وكيف ستتحقق.
5. نفّذ فقط ضمن الإذن الممنوح. التزم بالتوثيق الرسمي والمراجع المناسبة وفحص التراخيص.
6. شغّل الاختبارات المتاحة، وسجّل ما نجح وما فشل وما لم يمكن تشغيله.
7. حدّث قائمة التحقق وسجل الأدلة والمشاكل في الملف نفسه؛ لا تُنشئ مرجعًا منافسًا مبعثرًا.
8. لا تعلن اكتمال مرحلة قبل تحقيق شرط خروجها. العائق في ميزة لا يمنع العمل المستقل الآمن، لكنه يمنع إعلان نجاحها.
9. في نهاية كل دفعة: ملخص التغيير، نتيجة الاختبارات، المخاطر، والخطوة التالية.

- محجوب: يحتاج قرارًا أو إذنًا أو بيئة أو موقعًا للاختبار.

## 2. عقد النطاق والقرارات الثابتة

- المنتج شخصي للمستخدم، وليس مشروع نشر عام حاليًا.
- Windows أولًا؛ Android لاحقًا بعد استقرار Windows وبموافقة منفصلة.
- الهدف: تجربة IDM المألوفة مع جامع روابط وحِزم شبيه بـJDownloader.
- AB Download Manager هو الأساس المختار مبدئيًا. لا بناء من الصفر ولا تغيير للقاعدة بصمت.
- المحرك والبيانات والمنطق القابل للمشاركة منفصلة عن تكاملات Windows؛ واجهة Android لاحقًا مناسبة للجوال، وليست تصغيرًا لنافذة الكمبيوتر.
- لا حساب سحابي إجباري، لا إعلانات، لا تتبع استخدام افتراضي، ولا رفع كلمات مرور أو Cookies أو سجل تحميلات لخادم تابع لنا.
- واجهة Windows قريبة جدًا من IDM في توزيع العناصر والتفاعلات والاختصارات، مع اسم وأصول رسومية خاصة بنا.
- إعدادات شاملة لكن منظمة: وضع أساسي، وضع متقدم، بحث، شرح للقيم، وإعادة ضبط لكل قسم.
- المستخدم غير مطالب ببرمجة Plugins أو اختيار كل المواقع الآن. إطار الإضافات أولًا، ودعم المواقع لاحقًا من الإعدادات.
- لا تشغيل تلقائي لملفات EXE أو مثبتات الألعاب. فك الضغط اختياري. لا حذف تلقائي للأجزاء افتراضيًا.
- لا وعد بدعم كل المواقع أو بسرعة تتفوق على IDM قبل قياسات حقيقية.
- لا دمج وحدات تجاوز DRM أو كسر حماية وصول المواقع ضمن هذا النطاق. تعامل Captcha المعتمد: مسار مدعوم لكل موقع، مع تدخل المستخدم عند الحاجة، دون وعد بحل آلي شامل.
- لا حذف ميزة طلبها المستخدم بسبب صعوبتها، إلا إذا ألغاها المستخدم صراحة؛ صنّف ما تعذر مؤجلًا أو محجوبًا واطلب القرار عند الحاجة.
- دعم YouTube مطلب صريح عبر وحدة وسائط قابلة للتحديث، مع اختيار الجودة والصوت والترجمة والقوائم حيث يدعم المصدر، ودون وعد بالمحتوى المحمي أو غير المصرح به.

## 4. تصحيحات ملزمة للوعود السابقة

1. Plugin ليس دعمًا سحريًا: إضافات JDownloader لا تعمل تلقائيًا داخل برنامجنا، وتغيير المواقع قد يكسر إضافاتها.
2. وجود part01 إلى part19 لا يثبت أن الحزمة تتكون من 19 جزءًا. العدد المتوقع يجب أن يستند إلى قائمة مصدر أو بيانات أرشيف أو دليل آخر؛ وإلا يظهر «غير معروف».
3. تشابه اسم الملف أو حجمه لا يكفي لخلط أجزاء من مرايا مختلفة أو إصدارين للعبة.
4. حل Captcha في المتصفح لا يضمن نقل الجلسة أو رابط التحميل للتطبيق. تعامل معها حسب الموقع، ووفّر الرجوع للمتصفح عند عدم الدعم.
5. نجاح نقل Cookies لا يلغي قيود الموقع أو صلاحية الرابط أو حدود الحساب.
6. تشفير نقل HTTPS ليس DRM. ولا يُصنّف كل HLS مشفّر تلقائيًا كـDRM؛ صنّف الحالة بدقة دون وعد بالتعامل مع محتوى محمي.
7. إعداد الملف يخصص القيم الموروثة لكنه لا يتجاوز سقف السرعة أو الاتصالات العام أو قيود الخادم.
8. تصريح صلاحيات Plugin في ملف لا يصنع عزلاً أمنيًا. لا تُسمَّ الإضافة معزولة دون آلية إنفاذ واختبارات سلبية.
9. «نفس البرنامج» لا يعني مزامنة سحابية تلقائية بين الأجهزة؛ تلك ميزة مستقبلية تحتاج قرارًا منفصلًا.

## 5. هيكل التنفيذ المقترح

احتفظ بوحدات المصدر المناسبة، ولا تعِد تقسيم كل المشروع لمجرد مطابقته للأسماء التالية. المطلوب حدود واضحة للمسؤوليات:

- Download Core: HTTP، الأجزاء، الاستكمال، التحقق من هوية الملف وسلامة البيانات.
- Task/Queue Service: المهام، الحالات، الجدولة، إعادة المحاولة، حفظ التقدم.
- Link Collector: استخراج الروابط، إزالة التكرار، عمق الفحص وحدوده.
- Package Service: أجزاء الحزمة، عددها المتوقع، المرايا، كلمة مرور الأرشيف.
- Plugin Interface: إضافات جمع الروابط وإضافات الاستضافة، التوافق والإعدادات.
- Browser Bridge: قناة موثقة بين إضافة المتصفح والتطبيق، مع التحقق من كل طلب.
- Media/Archive Services: معالجة الوسائط وفك الضغط والتحقق، دون تشغيل ملفات.
- Windows UI/Integration: الواجهة، Tray، الإشعارات، Clipboard، إجراءات الجهاز.
- Settings/Security: القيم الافتراضية، الأولويات، حماية الأسرار، التحديث والنسخ الاحتياطي.

### نماذج البيانات التي يجب حسمها مبكرًا

DownloadItem، Package، Part، Source/Mirror، Queue، SiteProfile، CredentialReference، PluginDescriptor، CaptchaTask، VerificationResult.


يجب حفظ رابط الصفحة الأصلي منفصلًا عن رابط التحميل المؤقت، وربط المهمة بحزمتها وإضافتها وحسابها دون نسخ الأسرار إلى كل سجل. لا تفترض استخدام قاعدة بيانات جديدة؛ قيّم تخزين AB أولًا ثم وثّق القرار.

### P2 — موثوقية المحرك والحفظ

- [ ] P2-01 التحقق من التنزيل باتصال واحد ومتعدد وديناميكي باستخدام ملفات معروفة البصمة. الحالة الجزئية: اتصال Range واحد في E013 وثلاثة أجزاء HTTP حقيقية تُكتب في ملف واحد وتطابق البايتات وSHA-256 في E014؛ ما زال التقسيم الديناميكي الكامل مطلوبًا.
- [x] P2-02 اختبار Range وContent-Range وETag/Last-Modified واستجابات 200/206/416، ومنع استكمال ملف تغيّر. تحقق E013 من الاستجابات والـHeaders، وتحقق E014 من رفض الاستكمال عند تغير الطول أو ETag ومن السماح بالتوافق عند غياب ETag مع ثبات الطول.
- [ ] P2-03 حفظ التقدم بصورة متسقة مع البيانات المكتوبة؛ اختبار التعطل القسري والاستعادة. الحالة الجزئية: E015 يثبت Flush قبل حفظ Snapshot، وعدم حفظ تقدم عند فشل Flush، واستعادة آخر Snapshot مكتمل مع تجاهل ملف `.tmp` منقطع، وإظهار فشل التخزين؛ يبقى اختبار قتل عملية مستقل أثناء تنزيل أكبر.
- [ ] P2-04 التوقف والاستكمال والإلغاء وحذف القائمة مقابل حذف الملف؛ تأكيد واضح قبل الحذف المادي. الحالة الجزئية: E016 يثبت Pause/Resume لجزء HTTP من Offset دقيق مع بصمة نهائية، وسياسة إبقاء ملف المكتمل ما لم يحدد المستخدم حذفه وحذف بقايا غير المكتمل؛ نافذة التأكيد موجودة ومراجعة، ويبقى اختبار مستوى `HttpDownloadJob`/الواجهة كاملًا.
- [ ] P2-05 إعادة محاولة محدودة بتأخير متزايد؛ احترام 429 وRetry-After وحدود كل موقع. الحالة الجزئية: E017 يربط Backoff محدودًا بمساري HTTP وHLS، ويحفظ `Retry-After` بصيغتي الثواني وHTTP-date حتى عبر الأخطاء المغلفة، ويختبر استجابة 429 حقيقية؛ تبقى سياسة وحدود مستقلة لكل موقع.
- [ ] P2-06 معالجة انقطاع الإنترنت وTimeout وأخطاء 5xx وتغير الشبكة دون إتلاف الملف. الحالة الجزئية: E018 يثبت التعافي من 503 مؤقتة وRead Timeout وقطع اتصال بمنتصف النقل، مع استكمال Range من Offset المكتوب ومطابقة الملف والبصمة؛ يبقى اختبار تبدل واجهة الشبكة الفعلي وانقطاع أطول من كل المحاولات.
- [x] P2-07 حد سرعة واتصالات كلي، وحدود للموقع والطابور والملف مع أولويات مفهومة. E019 يثبت مشاركة المحدد العام وسقف اتصالات الملف واحترام `minPartSize` بعد BUG-002؛ E020 يثبت سجل Host المشترك لـHTTP وHLS؛ E021 يثبت التخزين والواجهة وقواعد Wildcard؛ وE022 يجمع سقف الطابور والملف والموقع دون تجاوز أو تجويع.
- [x] P2-08 معالجة امتلاء القرص والأسماء المتعارضة والأسماء العربية والمسارات الطويلة والملفات الأكبر من 4GB. يثبت E023 فشلًا آمنًا قبل لمس ملف موجود عند نقص المساحة، وترقيم أسماء عربية متعارضة دون فقد الامتداد، ومسارًا يتجاوز 300 محرف، وملفًا Sparse أكبر من 5GB؛ وأغلق BUG-003 حالة الحجم صفر.
- [x] P2-09 عرض «الحجم/الوقت غير معروف» بدل تقديرات مضللة عندما تغيب البيانات. يثبت E024 أن الطول المجهول لا ينتج نسبة أو ETA، وأن HLS لا يعرض طولًا متفائلًا كوقت دقيق، وأن مجموع تحديد يحتوي عنصرًا مجهولًا أو Overflow يبقى مجهولًا.
- [ ] P2-10 تثبيت الجداول والطوابير والتصنيفات وإعادة المحاولة، مع عدم تكرار المهام بعد إعادة التشغيل. **قيد إعادة التحقق ضمن RF01–RF03:** يبقى E025 دليلًا ناجحًا لإصلاح العضوية المكررة والتوافق مع JSON القديم واختيار سجل واحد عند الإقلاع، لكنه لا يشغّل Retry الفعلية لـHTTP/HLS ولا يثبت حدود الطابور والجدولة والإيقاف بعد Restart. لا يعاد وضع `[x]` قبل C01–C17 ذات الصلة واختبارات Job حقيقية.

شرط الخروج: اجتياز T01–T08 وT18 ذات الصلة أدناه. لا تحسين سرعة على حساب سلامة البيانات.

- [ ] P8-04 اختبار شامل على Windows الفعلي والمتصفحات المعتمدة؛ توثيق ما تم على جهاز المستخدم وما تم في بيئة أخرى.
- [ ] P8-05 قياس سرعة/CPU/RAM/قرص في ظروف قابلة للمقارنة، **ثم إصلاح مصادر الاستهلاك المرتفع وإعادة القياس لإثبات التحسن**؛ لا يُغلق بمجرد تشغيل أداة قياس. قياس قبل/بعد على نفس جهاز Windows ونفس سيناريو الاختبار، مع حفظ CSV ومقارنة مقابل IDM عند توفره؛ ليس عدد الاتصالات الأعلى ضمان سرعة أعلى.
- [ ] P8-06 اختبار 1,000 و10,000 رابط ودفعات حِزم دون تجمد الواجهة؛ تحديد ميزانية أداء بناءً على القياس.

**شرط إغلاق M09/P8-05 (الأداء):** استخدم `scripts/Measure-WindowsDownloadManager.ps1` لأخذ عينات process-tree لـ`WorkingSetMiB` و`PrivateBytesMiB` و`CpuMachinePercent` وعدد Threads/Handles مع SHA واضح؛ نفذ **idle warm/idle minimized، نافذة التنزيل مفتوحة ومغلقة، عنصر واحد، تنزيلات متزامنة، pause/resume، وبعد 15 دقيقة خمول**. قارن نفس الجهاز ونفس الشبكة والحمل مع IDM إن توفر، وافحص رسم السائل وتواتر تحديث الواجهة وCaching وPool الاتصالات وBuffering وRelease للموارد بعد الإغلاق. **القياس تشخيص، لا إصلاح تلقائي**: وثق أسوأ Hotspots، أصلحها فعليًا في المصدر مع اختبارات منع رجوع، ثم نفذ المقارنة قبل/بعد وقرر الميزانية المقبولة. لا تقبل «استهلاك منخفض» دون أدلة، ولا تبالغ في التخفيض على حساب سرعة التحميل أو الوظائف.

- [ ] P8-07 مراجعة الأمان والتراخيص والأسرار وتحديثات الإضافات؛ لا شهادة أمان مطلقة.

## 8. فهرس الإعدادات المطلوب

الإعدادات قابلة للوراثة: عام ← موقع ← حزمة ← ملف، مع أسقف عامة صارمة. اعرض القيمة الفعالة ومصدرها للمستخدم عند التعارض.

| --- | --- |
| عام وواجهة | اللغة، 8 عائلات ألوان × Light/Dark، اتباع النظام، حزمة الأيقونات وحجمها، حجم العناصر، الأعمدة، Toolbar، الاختصارات، Drop Target، زر الفيديو العائم، سلوك الإغلاق وTray |

| الطوابير والجدولة | ترتيب وأولوية، بدء/توقف، تكرار، حصة بيانات، إجراءات الإكمال |
| المتصفح وClipboard | التقاط تلقائي، استثناءات، إرسال صفحة، مراجعة قبل البدء، الصلاحيات |
